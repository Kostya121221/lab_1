# Лабораторная работа № 1: структуры данных

Реализация на C++17. Структуры объявлены через `struct`, операции вынесены в отдельные функции и разделены по файлам: `array.cpp`, `singly_list.cpp`, `doubly_list.cpp`, `stack.cpp`, `queue.cpp` и `avl_tree.cpp`. Общие операции с контейнерами находятся в `storage.cpp`, работа с JSON — в `storage.cpp`; объявления и типы разделены по заголовкам: `array.h`, `singly_list.h`, `doubly_list.h`, `stack.h`, `queue.h` и `avl_tree.h`. Общие интерфейсы вынесены в `storage.h`, `storage.h`, `storage.h`, `storage.h` и `storage.h`. Команды разбираются через `enum class` и `switch`. Для JSON используется готовая библиотека nlohmann/json.

## Сборка

На Ubuntu установи инструменты сборки и nlohmann/json:

```bash
sudo apt update
sudo apt install build-essential nlohmann-json3-dev cmake
make
```

Запуск интерактивного режима:

```bash
./dbms --file file.json
```

Выполнение одной команды:

```bash
./dbms --file file.json --query 'CREATE M numbers'
./dbms --file file.json --query 'MPUSH numbers 10'
./dbms --file file.json --query 'MREAD numbers'
```

Выйти из интерактивного режима: `EXIT`. Список команд: `HELP`.

## Формат JSON

Все контейнеры лежат в одном JSON-объекте. Имя контейнера используется как ключ, а тип и содержимое записываются в поля `type` и `data`:

```json
{
    "numbers": {
        "type": "array",
        "data": ["10", "20"]
    },
    "myStack": {
        "type": "stack",
        "data": ["second", "first"]
    },
    "myTree": {
        "type": "tree",
        "data": ["10", "20", "30"]
    }
}
```

Имена контейнеров общие для всех типов. Например, нельзя создать стек `numbers`, если массив `numbers` уже существует. В `main.cpp` JSON читается при запуске через `nlohmann::json::parse()`, а после каждой команды записывается через `dump(4)`. `storage.cpp` только преобразует JSON в структуры и обратно. Программа читает и записывает формат, в котором каждый контейнер содержит поля `type` и `data`.

## Команды

- `CREATE <M|F|L|S|Q|T> <имя>` — создать контейнер.
- `DROP <тип> <имя>` — удалить контейнер целиком.
- `PRINT <тип> <имя>` — вывести контейнер.
- `SAVE` — записать текущее состояние. Изменения также автоматически сохраняются после каждой команды.
- `HELP` и `EXIT` — справка и завершение работы.

`M` — динамический массив: `MPUSH`, `MINSERT`, `MGET`, `MSET`, `MDEL`, `MLEN`, `MREAD`.

`F` — односвязный список: `FPUSH`, `FPUSHFRONT`, `FINSERTBEFORE`, `FINSERTAFTER`, `FDEL`, `FDELHEAD`, `FDELTAIL`, `FDELBEFORE`, `FDELAFTER`, `FGET`, `FREAD`, `FSEARCH`.

`L` — двусвязный список: `LPUSH`, `LPUSHFRONT`, `LINSERTBEFORE`, `LINSERTAFTER`, `LDEL`, `LDELHEAD`, `LDELTAIL`, `LDELBEFORE`, `LDELAFTER`, `LGET`, `LREAD`, `LSEARCH`.

`S` — стек: `SPUSH`, `SPOP`, `SGET`, `SREAD`.

`Q` — очередь: `QPUSH`, `QPOP`, `QGET`, `QREAD`.

`T` — AVL-дерево: `TINSERT`, `TSEARCH`, `ISMEMBER`, `TDEL`, `TGET`, `TREAD`. Повторяющиеся значения не вставляются. Значения сравниваются как строки, поэтому порядок лексикографический.

Индексы массива и списков начинаются с нуля. Для чтения односвязного или двусвязного списка в обратном направлении используется `FREAD <имя> REVERSE` или `LREAD <имя> REVERSE`.

## Особенности реализации

Односвязный список организован по принципу указателя на голову: функции вставки и удаления работают с цепочкой узлов и обновляют `head`. Указатели `tail` и отдельный счётчик длины для него не хранятся, поэтому добавление в конец и удаление последнего элемента требуют прохода по списку и имеют сложность O(n).

В двусвязном списке общие действия по вставке между двумя узлами и удалению узла вынесены в отдельные функции. Стек и очередь используют прямые операции над вершиной и началом/концом соответственно.

## Пример AVL-дерева

```text
CREATE T tree
TINSERT tree 30
TINSERT tree 20
TINSERT tree 10
TREAD tree
TSEARCH tree 20
TDEL tree 20
TREAD tree
```

Перед удалением вывод будет `[10, 20, 30]`, после удаления — `[10, 30]`.

## Вывод при добавлении элементов

При успешной вставке команды выводят добавленное значение в формате `-> <значение>`: `MPUSH`, `MINSERT`, операции вставки списков, `SPUSH`, `QPUSH` и `TINSERT`. Если вставка не удалась (например, индекс вне диапазона или значение уже существует в AVL-дереве), выводится сообщение об ошибке.


### Упрощённая обработка данных

JSON-объект является хранилищем именованных структур. Для выполнения команды нужная структура временно загружается из JSON в самописный массив, список, стек, очередь или AVL-дерево; после изменения её значения напрямую записываются обратно в JSON. `std::map` и `std::vector` в C++-части не используются. Библиотека `nlohmann/json` оставлена для чтения и записи JSON.


## Организация C++-части

У каждой структуры есть отдельный заголовочный файл с описанием узлов/данных и объявлениями операций: `array.h`, `singly_list.h`, `doubly_list.h`, `stack.h`, `queue.h`, `avl_tree.h`. Реализация находится в одноимённом `.cpp`. Общие объявления вынесены в `storage.h`, `storage.h`, `storage.h` и `storage.h`.

JSON остаётся основным хранилищем между командами. Обработчик загружает нужную структуру из JSON, выполняет операцию, сохраняет результат и освобождает временную память. Вспомогательные `std::vector` и `std::map` для данных структур не используются в этой версии.


### Упрощённая организация C++-части

- `array.h/.cpp`, `singly_list.h/.cpp`, `doubly_list.h/.cpp`, `stack.h/.cpp`, `queue.h/.cpp`, `avl_tree.h/.cpp` — соответствующие структуры данных и операции над ними.
- `main.cpp` — разбор команд и основной цикл программы.
- `storage.h` — тип команды, аргументы и объявления обработчиков.
- `storage.h/.cpp` — работа с JSON, создание/удаление именованных контейнеров и общий вывод.

Удалены отдельные `common.h`, `handlers.h` и `database.h`: их небольшие объявления объединены с логически близкими заголовками. `database.cpp` объединён с `storage.cpp`, поскольку обе части управляют данными, представленными в JSON.
